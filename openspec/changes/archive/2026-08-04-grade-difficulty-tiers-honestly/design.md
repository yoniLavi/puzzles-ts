# grade-difficulty-tiers-honestly — design

## D1: The survey (task 1)

**27 games have two or more difficulty tiers.** 23 already grade honestly; **four
did not** — Bricks and Mathrax (named in the proposal), plus **Salad and Ascent**,
which the proposal flagged as unchecked and which turned out to be the two worst
offenders in the collection.

### The instrument was wrong first, and the correction found a 27th game

The first sweep enumerated tiered games by grepping for `DIFF_*` constants and
found 26. **That missed Bridges**, whose tiers are `DIFFICULTY_NAMES = ["Easy",
"Medium", "Hard"]` with a plain `difficulty: number` param. It was caught only
because the owner's message typed "Bridges" where it meant "Bricks" and the name
was not in the list.

The correction is cheap but the lesson is not: re-running the sweep as *"games
mentioning difficulty that have no `DIFF_` constant"* produced seven candidates
(abcd, bridges, clusters, crossing, netslide, slide, sticks), of which exactly one
— Bridges — has real tiers, and Bridges grades honestly. So the defect list is
unchanged and the *count* is not.

**This matters beyond this change**: `add-game-difficulty-contract` opens by
measuring "26 games carry `DIFF_*` constants" and proposes a guard that *"the
declared tier count matches the game's own `DIFF_*` constants"*. Both inherit this
blind spot — a game that spells its tiers differently is never enumerated, so the
guard cannot fire on it. That change should enumerate from the registry and
`paramConfig`, not from a constant-naming convention.

### The two honest idioms — a grep for one finds false defects

An honest gate comes in two shapes, and only the first contains the string
`diff - 1`:

1. **Explicit lower-tier rejection** — solve at `diff - 1`; reject on success.
   *(15 games: group, keen, lightup, loopy, magnets, map, pearl, rome, seismic,
   singles, slant, spokes, tents, unequal, unruly.)*
2. **The solver reports the difficulty it needed** — accept only when
   `achieved === requested`. Strictly better: one solver run, not two.
   *(7 games: boats, dominosa, galaxies, solo, towers, tracks, undead. Bridges
   uses idiom 1.)*

Every one of the 23 was confirmed by **reading its acceptance gate**, not by the
grep that shortlisted it. Skipping that step would have reported seven false
defects.

### The four defects, measured

Rates are over this repo's own solver. "Fixtures" are the frozen C descriptions;
"fresh" is boards generated by the shipped generator at fixed seeds.

| Game | Tiers | Gate before | Misgraded (fixtures) | Misgraded (fresh) |
|---|---|---|---|---|
| **Salad** | Normal, Extreme | none at all | **12 / 13 Extreme** | **71 / 80** |
| **Ascent** | Easy…Hard | none at all | 7 / 22 above Easy | 56 / 180 |
| **Bricks** | Easy, Normal, Tricky | probes at *Easy* whatever the tier | **4 / 4 Tricky** | **40 / 40 Tricky** |
| **Mathrax** | Easy…Recursive | none at all | 3 / 23 above Easy | 11 / 120 |

Salad is the headline: **its Extreme setting was a Normal board 92% of the time**,
and the one genuinely-Extreme fixture is a single configuration (letters 8×8).

**Salad's fixture recorded the defect and the test asserted it as correct.** The
fixture carries `solverDiff`, "lowest difficulty at which the C solver finishes",
and the differential asserted the board needs *that* — not the tier it was
generated at. A test that asks "does this board need the difficulty the fixture
says it needs" cannot fail when the fixture says the wrong difficulty. The
misgrade was sitting in committed data, green, for as long as the port has
existed.

### Two categories deliberately *not* counted as defects here

- **Declared size caps.** Dominosa, Solo, Towers and Tracks silently lower the
  requested tier for sizes that cannot support it (`if (w <= 3) diff = HARD`).
- **Retry-exhaustion downgrades.** Map and Unequal drop a level after `MAXTRIES`;
  Boats steps down when generation fails outright.

Both ship a board below the tier the player selected — *the very defect this
change removes*, with a known trigger rather than by chance. They are recorded as
known deviations rather than fixed, because each needs its own measurement of
which sizes are genuinely impossible, and because the rule they should converge
on is the one this change establishes (**refuse, don't downgrade**, D3). Naming
them is the point: "eventually consistent" needs a written destination.

## D2: Keep the differential — the Spokes shape, four times

Every one of these generators is solver-gated at each removal, so correcting the
gate changes every description above the easiest tier, which would cost the
byte-match oracle that validates generator + solver + codec in one assertion.

All four take `spokes`' shape verbatim: an options object with a single
`upstreamLooseGate?: boolean`, defaulted off, documented "nothing else should
ever set it", and set in exactly one place — the differential's `newDesc`
wrapper. **All four differentials still byte-match the C**, so no fixture was
re-founded and nothing was re-recorded (which, post-`retire-c-engine`, would be
impossible anyway).

The oracle's residual blind spot is stated per game: the two or three lines
inside the `if (!loose)` branch.

## D3: Refuse an unbindable tier; never silently downgrade it

Two tiers turned out to have **no boards at all**, so a correct gate would spin
for ever. Both are refused in `validateParams` when `full` is true — so a saved
game or a game ID carrying its own description still loads, and only *generation*
is refused.

- **Bricks Tricky** (all sizes). See D4.
- **Mathrax order 3, Normal and Recursive.** 0 binding boards in 3,000 candidates
  each; order 3 *Tricky* is fine at ~9.5 candidates per success, and every tier at
  order ≥ 4 costs ~1.0–2.7. A 3×3 grid has four intersections, which is not enough
  structure to separate Easy from Normal.

**Why refuse rather than cap.** The four size-capping games above are the
alternative, and a silent cap is this change's own defect wearing a justification:
the player asks for Extreme, gets Hard, and is told nothing. Refusal is also the
existing precedent for *"this configuration has no puzzles"* — Loopy rejects
Penrose kite/dart at width 3 the same way.

`newBricksDesc` additionally throws immediately on an unbindable tier rather than
letting the retry bound burn 100,000 candidates: these generators are synchronous,
so a loop that cannot succeed owns its thread and `testTimeout` cannot fire
(`engine/retry-limit.ts`).

## D4: Bricks' Tricky tier is empty, and that is a measurement not a judgement

Bricks' tiers are lookahead depth: Easy assumes nothing; Normal assumes a cell and
looks for an Easy-level contradiction; Tricky lets that sub-solve recurse in turn.
Upstream's own documentation conceded *"Selecting Tricky difficulty may generate a
puzzle at Normal difficulty instead"*, and the port preserved that as an intended
quirk (`add-bricks-ts-port` D3). **It is not "may" — it is always:**

- 999 / 999 boards generated at Tricky (5×5, 7×6, 8×5) solve at Normal;
- 40 / 40 in a separate sweep at 7×6 and 10×8 — both upstream presets;
- 4 / 4 frozen C Tricky fixtures, including 12×8;
- 480 boards from a real stripping walk: depth-1 and depth-2 verdicts **identical
  throughout**;
- 77 boards chosen *because Normal cannot solve them* — the only region where
  Tricky could distinguish itself — Tricky solved **none**.

The port is faithful; `git show` of the deleted `bricks.c` has the same
`bricks_solver_recurse(state, maxdiff)` → `bricks_solve_game(state, maxdiff - 1)`
structure. Bricks' constraints (no three in a row, gravity support, clue counts)
are local enough that a contradiction either surfaces immediately or not at all,
which is a structural reason to expect *more* depth to buy nothing either.

So Tricky is **not offered**, the two Tricky presets are gone, and `DIFF_TRICKY`
survives in the solver as "try as hard as you can" for hints, Solve and
mistake-checking, where the depth costs nothing and asks no question about which
puzzles exist.

**Bricks' Normal boards are bit-identical to before.** For Normal, `diff - 1` *is*
`DIFF_EASY`, so upstream's gate and the corrected one agree; the differential's
Normal fixtures byte-match on the unmodified path. An apparent 2× slowdown in one
measurement run was box noise, not the change.

## D5: The stale-scratch trap, hit once in this change

The first Ascent gate reused the generator's `SolverScratch` for its "does the
tier below solve this?" probe. That is wrong twice over, and the measurement
caught it — Hard still showed 3/60 misgraded after the "fix":

- `SolverScratch.foundEndpoints` **persists across solves by design** (a
  byte-match-critical upstream quirk) and, once true, permanently *weakens* the
  solver. So the probe asked a weakened solver whether the easier tier copes, and
  under-rejected.
- The probe also left its own marks and `foundEndpoints` behind for the next
  candidate, making which boards ship depend on the gate's side effects.

This is precisely the defect `spokes` documents — *"its verdict is about the
leftover position instead of about the puzzle"* — reproduced in a second game by
someone who had read that note the same afternoon. The fix is a fresh scratch per
probe, which answers the question a player would ask: can the tier below solve
*this board*, from nothing?

**Reusable form: a tier probe must run on state that carries nothing from the
candidate that preceded it.** That two games got this wrong independently is the
strongest argument in this change for `add-game-difficulty-contract`'s shared
`solveAtCap` — a helper each game cannot get subtly wrong on its own.

## D6: Cost, measured by the tail

Post-fix, **0 / 480 boards misgraded** across all four games, every tier and
configuration sampled. Generation cost (N=30 per cell):

| Config | Median | p90 | Max |
|---|---|---|---|
| bricks 7×6 Normal | 85 ms | 243 ms | 408 ms |
| bricks 10×8 Normal | 592 ms | 2.1 s | 2.2 s |
| ascent (all modes/tiers) | 2–6 ms | ≤ 21 ms | 39 ms |
| mathrax o5–o7 Normal/Tricky | 3–24 ms | ≤ 31 ms | 125 ms |
| salad letters 5×5 / 8×8 Extreme | 49 / 155 ms | 153 / 671 ms | 610 ms / 1.1 s |
| **salad numbers 5×5 Extreme** | **1.6 s** | **6.0 s** | **6.9 s** |

Only Salad's Number Ball mode is genuinely expensive, because Extreme boards are
genuinely rare there. Counted directly rather than inferred from wall clock, over
25 runs per preset: `numbers 5×5 n3` costs a **median of 486 candidates and a
worst of 4,419**; other configurations cost 2–823.

**That worst case is 44% of the house retry bound**, so `retryLimit`'s default of
10,000 would eventually fire on a perfectly legal seed — and exhaustion throws, in
a player's face. Salad's bound is raised to 50,000, which is `retry-limit.ts`'s own
*"wrong for a rare-but-legal seed"* case: the bound stays, far enough out that
reaching it means a tier became unreachable rather than merely thin. No Salad
preset uses Extreme, so this is the Custom-dialog path only.

## D7: What replaces the oracle where it was never lost

Nothing was lost — all four differentials still byte-match (D2). The tier property
is *added* on top, as a per-game test asserting a generated board solves at its
tier and **not** at the one below. Each was **proved to fail against the old
behaviour** before being trusted (10/11 Salad presets, 4/7 Ascent cases, 2/6
Mathrax cases; Bricks' is the refusal itself), because a tier test that passes
either way measures nothing.

## D8: Deliberately not done

- **The cross-game guard.** These are four per-game tests. One test iterating
  every tiered game needs a uniform way to call 27 different solvers at a cap —
  which is exactly `add-game-difficulty-contract`. This change gives that one four
  worked examples and, in D5, a defect that argues for it.
- **The other 23 help pages.** The "you get the difficulty you chose" sentence is
  now true for all 27 tiered games but is written on only these four. Sweeping the
  rest is a small, mechanical follow-up, deliberately not bundled with a change
  that alters generated boards.
- **Re-balancing what a tier means.** This makes the labels true, not the curve
  different.
