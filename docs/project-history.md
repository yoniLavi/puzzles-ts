# Project history

**This is the record, not the rules.** Nothing here needs to be read to do a
piece of work: [`AGENTS.md`](../AGENTS.md) holds how this project is built, the
[`docs/games/`](games/README.md) guides hold the followable procedures, and
`openspec/specs/` holds what is normatively true. This file exists so that
those documents do not have to carry a chronicle in order to keep one.

It is worth reading once, and worth searching when you want to know *why* a
decision looks the way it does — most entries record what was tried, what it
cost, and what it found. Where an entry states a rule that still binds, that rule
also lives in `AGENTS.md` or a spec; if you ever find one here that does not,
that is a bug in the split and the rule should be lifted out.

Entries are in the order the work happened. Change ids name the openspec change,
which is archived under `openspec/changes/archive/` with its full detail.

## How the C was retired: per game, as each port shipped

A game's `puzzles/<game>.c` is deleted once that game's TS port has landed and shipped — deletion is **per game**, not deferred to a whole-collection endpoint. C/WASM remains the runtime for unported games until each is ported. The collection is fully migrated, and `puzzles/` removed entirely, only when the last game lands. The point: don't carry a per-game C fallback past the moment its TS replacement is trusted in production.

## The migration order, as planned and as it went

Top-down, product-value first:

1. **TS midend + `Game` interface** — the keystone. **Landed** (`ts-midend-and-game-interface`): `src/engine/` ships the `Game` interface, the `Midend`, the runtime per-game registry, and the clean save codec, behind the unchanged Comlink surface, with an empty registry.
2. **Pattern-establishing game** — **Flip ported and at owner-confirmed parity 2026-05-20** (`add-flip-ts-port`). Shipped broken: midend didn't repaint, no animation. Then took three iterations on the rendering pipeline — each surfaced a distinct real defect: midend-doesn't-repaint (`5c5eba4`), animated-first-frame flicker (`b7dc206`), then `9823acd` mirrored `midend.c`'s first-draw too literally and caused ResizeController-driven cache wipes; `b49bfdb` reshaped that into a side-effect-free `Midend.size` + explicit `canvasCleared` and moved the bg fill into each game's `!ds.started` branch (engine emits no pixels of its own); finally `b1b0dd6` fixed a state-machine bug where `Midend.timer` accumulated `flashTime` unconditionally, causing Flip's solve-celebration flash overlay to fire on every animated move. The reusable port pattern (engine contract, `TS_PORTED` catalog seam, differential checks) stands. Lessons spec-enforced: green suite ≠ parity (`add-parity-gated-registration`); the engine paints no pixels of its own and `Midend.size` is informational (`fix-flip-canvas-reshape`). A scene-graph `Game.scene()` contract was considered (`scaffold-scene-graph-game-contract`), scaffolded, implemented (`add-scene-graph-reconciler`), and **withdrawn 2026-05-21** after owner-acceptance surfaced a visible animation perf regression and the broader question — does the pivot pay back inside the migration window? — concluded no. Postmortem: `openspec/postmortems/2026-05-21-scene-graph-withdrawal.md`. The doctrine fixes above (engine emits no pixels, side-effect-free `Midend.size`, `canvasCleared` as the only cache-stale signal) carry the per-game-cache-fragility weight on their own; future ports stay imperative with those doctrine fixes in place.
3. **Galaxies** — **landed and at owner-confirmed parity 2026-05-26** (`add-galaxies-ts-port`). The goal-4 game. Idiomatic TS port across `src/games/galaxies/{index,state,solver,generator,render,dsf}.ts` (~3000 lines vs ~4500 in C — smaller *and* more readable). `puzzles/galaxies.c` deleted. The cell↔dot association aid is the planned follow-up, now unblocked.
4. **Helper-extraction prep change** — **Landed 2026-05-26** (`extract-shared-helpers`): `src/engine/{colour-mkhighlight,pointer,dsf}.ts`. See "Helper extractions: status" below.
5. **Pattern-validation port** — **Pegs landed and owner-accepted 2026-05-26** (`add-pegs-ts-port`), validating the helper-extraction template; **Sixteen followed, landed 2026-05-27 and owner-accepted 2026-06-04** (`add-sixteen-ts-port`).
6. **Cross-game features** — the `hint()` hook **shipped** (`add-hint-system` 2026-05-27, deepened to plan-carrying hints by `add-hint-plans` 2026-06-10; Sixteen is the first implementer). The `findMistakes()` hook + Galaxies implementation **shipped** (`add-findmistakes-galaxies`) and the one-slot **quick-save** + combined **Check & Save** button **shipped** (`add-quick-save-check-save`) — both 2026-06-10, dev-verified, owner-acceptance pending. Item 6 is now closed (hint + mistake-check + quick-save all landed).
7. **Outward** — remaining games, simplest-first; leaf libs pulled in idiomatically as needed; worker existence re-evaluated once games are TS (it exists for heavy WASM; light TS games may not need it).
8. **`random.c`** is already TS (`random.ts`); keep it.
9. **`retire-c-engine`** — **landed 2026-08-01.** The terminal state: the C
   engine, the Emscripten build, the leaf-bridge flags and the worker's WASM
   path are gone. `puzzles/` was left holding upstream's help sources and the
   licences; the follow-up `rehome-upstream-help-sources` **landed the same day**
   and moved them to `help/upstream/` and `licences/`, deleting `puzzles/`.

**Where the order goes next (owner, 2026-08-01).** Every game is ported and the
authors' known-issue lists are reconciled, so:

1. ~~**`retire-c-engine`**~~ — **done, 2026-08-01.** See the entry at the end of
   "What's been done" for what it removed, and the two things the review of it
   found that the change had not anticipated.
2. **A round or two of refactoring** on the TypeScript-only codebase, so the work
   below lands on cleaner code. The 48 per-game differentials are the net for
   this: each imports a *frozen JSON fixture* and keeps working with no C
   present, and a refactor that changes a solver's verdict changes which boards
   exist — which is exactly what they catch.
3. **Then the improvements the released oracle unblocked** —
   `grade-difficulty-tiers-honestly` first (the tiers exist and merely fail to
   bind), then `add-clusters-difficulty-tiers` → `add-subsets-difficulty-tiers` →
   `add-sticks-difficulty-tiers` in that order (increasing amounts of deduction
   to invent), plus `add-latin-repeats-support`, `bound-abcd-generable-sizes` and
   `refine-slide-appearance`.
4. **Greenfield last**: Path, then Numgame.

**Added 2026-08-03 (owner), not yet slotted into the order above**: two input
changes, from the observation that `retire-the-upstream-help-tree` deleted a
*true* sentence when it removed Slide's "keyboard control is not yet supported"
status note. `add-slide-keyboard-control` closes that specific gap;
`audit-input-mode-parity` establishes the collection-wide bar the owner stated —
**maximum parity between mouse, touch and keyboard** — because nothing currently
does. The precedent for why that is not paranoia: `fix-touch-input-stylus-modifier`
found **nine of thirty-two** ported games completely deaf to touch, and found
them via an owner bug report rather than a test. Note
`add-slide-keyboard-control` and `refine-slide-appearance` both edit
`slide/render.ts`; whichever lands second owns the reconcile.

One consequence of that order, intended rather than accidental: **after
`retire-c-engine` a divergence is one-way.** With no C build there is no
answering "what would upstream have produced?" for a new question and no
re-baselining a fixture against it, so a deliberate divergence retires or
re-founds its fixture rather than re-recording it. `puzzles/` stays in git
history if a question ever genuinely needs it.

## The changes, in order, and what each one found

Recorded here as durable reference, not a changelog (commit history carries the detail):

- **Project setup**: openspec initialised; layered `LICENSE.md` + `CREDITS.md`; Vitest + a strict pre-commit gate (`tsc -b --noEmit` → `npm run lint` → `npm run test:run`).
- **`random.c` (TS impl half)** — `port-random-to-typescript`: corpus harness in-tree at `puzzles/auxiliary/random-trace.c`; corpus at `src/engine/random/__fixtures__/corpus.json` (6 fixtures, 66 calls); TS port in `src/engine/random/{index.ts, sha1.ts}`; replay test passes byte-for-byte.
- **`random.c` (bridge half)** — `wire-random-to-wasm`: TS owns canonical state, C holds integer handles, bridge via Emscripten `--js-library`, gated by `USE_TS_RANDOM` (CMake) + `VITE_USE_TS_RANDOM` (worker) (initially default OFF; later folded under `USE_TS_LEAVES` and flipped to default ON — see entries below). Five puzzles verified end-to-end through the bridge (cube/flip/mines/loopy/solo, 0 console errors).

  Sizing data for the next seam's "wire it up" half: ~40 min elapsed in the implementing session, dominated by ~25 min of docker rebuild latency across ~6 cold builds (eliminated by host-native build, see below). Four surprises captured in `wire-random-to-wasm/design.md` cost roughly one rebuild loop each: (1) `random.c` carries `misc.c`'s SHA-1 dep; (2) `build-emcc.sh` was baked into the docker image; (3) `tee` swallowed the docker exit code, masking a silent link failure; (4) `--js-library` only emits an env import when a C reference is live — needs `__attribute__((used))` keep-alive in `webapp.cpp`.
- **Build pipeline → host-native** (`remove-docker-emcc-build`): replaced `Docker/build-{emcc,icons}.{sh,Dockerfile}` with `scripts/build-{emcc,icons}.sh` driven by a brew-installed Emscripten + GTK+3 (see `Brewfile`); npm wrappers are `build:wasm`, `build:icons`, `build:assets`. Cold wasm build dropped from ~4 min (Docker) to ~1:51 (flag-OFF) / ~2:15 (flag-ON); incremental wasm rebuild is now ~2s, removing the iteration-latency tax. Side fix in `puzzles/emcc-dependency-info.py` resolves brew's symlinked `emcc` for license attribution. The Cloudflare Pages workflow inherited from upstream is disabled in this fork; rewiring it against the new scripts is left for whenever this fork wants its own CI/CD.
- **Pruned upstream frontends** (`prune-unsupported-frontends`): dropped every upstream platform this fork doesn't ship — Windows (`windows.c`, `winwix.mc`, `padtoolbar.bmp`, `puzzles.rc`), macOS (`osx.m`, `osx/`, `osx-help.but`), KaiOS (`kaios/` + the KaiOS-targeted `emcc.c`/`emcclib.js`/`emccpre.js`/`emcccopy.but` and `emscripten.cmake`), NestedVM (`nestedvm.c`, `nestedvm-toolchain.cmake`, `glob-symlinks.py`), Java applet (`PuzzleApplet.java`), Linux .desktop packaging (`puzzle.desktop.in`, `desktop.pl`), Windows MinGW toolchain helpers, and upstream's release infra (`Buildscr`, `CHECKLST.txt`, `Makefile.doc`, `webpage.pl`, `website.url`, `chm.css`, `benchmark.pl`, `benchmark.sh`). `puzzles/cmake/setup.cmake` then selected `webapp.cmake` (wasm via `WEB_APP=ON`) or `unix.cmake` (icons via GTK headless screenshots). `gtk.c`, `printing.c`, and `unix.cmake` were kept at that point (load-bearing for icons) and were later removed in `drop-icon-generation` once the icon pipeline became unnecessary; `ps.c` stays in `core_obj` (no measurable wasm size impact, defer to a future deletion checkpoint). From here on we diverge from medmunds on the frontend inventory; continue tracking upstream Simon Tatham for engine-side changes.
- **Root + src/ reorg** (`reorganize-repo-tooling`, `reorganize-src-layout`): vite plugin source moved to `vite-plugins/`, handlebars templates moved to `templates/`, build outputs consolidated under `/build/`. `src/` grouped by role: `screens/`, `dialogs/`, `components/`.
- **Pre-seam structure consolidation** (`consolidate-pre-seam-structure`): `src/native/` regrouped per ported module (`src/native/random/{index.ts, bridge.ts, sha1.ts, __fixtures__/, random.test.ts}`); `PLAN.md` folded into this `AGENTS.md`; `CLAUDE.md` symlinked to `AGENTS.md`; `openspec/AGENTS.md` renamed to `openspec/OPENSPEC_AGENTS.md` to avoid collision; `scripts/build-native.sh` added so harness binaries actually land in `/build/native/` as the build-pipeline spec already said they should.
- **Icon pipeline drop** (`drop-icon-generation`): deleted `scripts/build-icons.sh`, `puzzles/gtk.c`, `puzzles/printing.c`, `puzzles/cmake/platforms/unix.cmake`; dropped `gtk+3`/`pkgconf`/`imagemagick`/`oxipng` from `Brewfile`. `puzzles/cmake/setup.cmake` now auto-routes by `CMAKE_SYSTEM_NAME`: emscripten → `webapp.cmake`, native → new `platforms/native.cmake` (a minimal GTK-less platform file that keeps `scripts/build-native.sh` building the auxiliary harnesses). Per-puzzle thumbnails under `src/assets/icons/` are now a committed snapshot maintained per the new `puzzle-icons` spec — new puzzles need two PNGs produced by hand from the running PWA.
- **USE_TS_LEAVES umbrella + worker coherence check** (`add-use-ts-leaves-umbrella-flag`): one CMake option (`USE_TS_LEAVES`) and one Vite env var (`VITE_USE_TS_LEAVES`) gate the entire leaf-library bridge family at once. Per-module flags (`USE_TS_RANDOM`, future `USE_TS_COMBI`, …) survive as debugging overrides — set them explicitly to flip an individual seam against the umbrella in either direction. The worker enumerates WASM imports at instantiation (`assertWasmBridgesCoherent` in `src/puzzle/worker.ts`) and fails closed with a templated error if the CMake and Vite sides disagree (forward mismatch); reverse mismatch is silent by design. Each new bridge ports add one row to `FORWARD_MISMATCH_PROBES` and one `option(USE_TS_<MODULE> ... ${_default_ts_module})` line — that's the whole boilerplate.
- **Umbrella default flipped to ON** (`flip-ts-leaves-default-on`): zero-arg `npm run build:wasm && npm run dev` now produces the hybrid TS+C build that production runs. Pure C is now opt-in via `USE_TS_LEAVES=0` (paired with `VITE_USE_TS_LEAVES=0` on the worker side) — useful for bisecting "is this a TS-port regression or upstream-C behaviour?"
- **Doctrine pivot to top-down TS** (`pivot-to-top-down-ts`, 2026-05-18): the migration strategy was inverted. C went from immutable byte-oracle to readable reference + dev-time differential-check source; byte-identical characterization corpora dropped for behavioural tests + an advisory spot-check; seam order inverted from bottom-up (random→leaves→…→midend) to top-down (TS midend + `Game` interface first, then games simplest→Galaxies→outward, leaf libs lazily as idiomatic TS); C deletion is now per-game when each port ships; clean TS save format (old saves / pre-pivot shared IDs expendable; `random.ts` keeps future IDs stable); deliberate divergence from upstream is the point. Authoritative spec: `openspec/specs/ts-migration/spec.md`. The prior approach is preserved on branch `legacy/seam-by-seam-fidelity` + tag `pre-ts-pivot`. The obsolete `add-benchmark-soak` proposal (byte-diff hybrid-vs-pure) was retired. The `USE_TS_LEAVES` umbrella + coherence check still function as runtime mechanics but are no longer the migration *strategy* (migration is per-game now); a per-game switch is designed in the next change.

- **TS midend + `Game` interface keystone** (`ts-midend-and-game-interface`): `src/engine/` now holds the idiomatic `Game<Params,State,Move,Ui,DrawState>` interface (immutable state, GC not dup/free, union/boolean not int sentinels, discriminated `SolveResult`), the `Midend` orchestrator (move/undo/redo with a parallel move log, restart, solve→solved-with-help, preset-tree flattening, params validation, `params:desc`/`params#seed` ids, timer, size, redraw, existing `ChangeNotification` emission), the **runtime per-game registry** (the hybrid decision point — *not* a build flag), the clean versioned-JSON save codec, and a `TsWorkerPuzzle` adapter wired by a single dispatch seam in `src/puzzle/worker.ts`. The registry **ships empty**, so production is the byte-identical all-WASM path until the first port calls `registerGame(...)`. 22 behavioural/property tests drive a fake `Game` (no corpus). The drawing/size/config-UI contract is intentionally minimal — the first port refines it (an explicit interface-refinement allowance, not a spec breach).

- **First game port: Flip** (`add-flip-ts-port`): the pattern-establishing port. `src/games/flip/` implements `Game<FlipParams,FlipState,FlipMove,FlipUi,FlipDrawState>` (immutable state, shared frozen matrix, discriminated move, GF(2) Gaussian-elimination solver, `CROSSES` + `RANDOM` generators, flip-animation/win-flash timing, keyboard cursor, text format, redraw); `tree234` was ported lazily as a local idiomatic `SortedMultiset` (sorted-array set under a comparator) used only by the RANDOM generator. The keystone-deferred contract is resolved: `GameDrawing` widened to the full puzzle drawing API (the existing canvas `Drawing` satisfies it unchanged), `interpretMove` may return `UI_UPDATE` (cursor/UI change, redraw, no history entry — midend-handled), `colours(defaultBackground)` threaded through `EngineCore`/`Midend`/`TsWorkerPuzzle`, and `Game.setTileSize` added (upstream `game_set_size`, midend-driven from `size()`). `PuzzleEngineSurface` (new, `src/puzzle/engine-surface.ts`) is implemented by both `WorkerPuzzle` and `TsWorkerPuzzle`, deleting the `as unknown as WorkerPuzzle` dispatch cast (drift is now a compile error). **Per-game hybrid catalog seam**: the CMake `puzzle()` macro gained `TS_PORTED` — a TS-ported game keeps `catalog.json`/`puzzleIds` metadata (via a `ts_ported_names` list unioned by `webapp.cmake`) but builds no `<name>.c`/wasm; `puzzles/flip.c` deleted (per-game C deletion). Differential check: the transient `puzzles/auxiliary/flip-trace.c` was used then removed with flip.c; the durable forms are the **gated** frozen-snapshot `src/games/flip/flip-differential.test.ts` (CROSSES exact vs `__fixtures__/flip-c-reference.json`, RANDOM solvable) and the **advisory, ungated** live `scripts/diff-flip.test.ts` (run via `scripts/diff-flip.vitest.config.mts`). Result: CROSSES matches C byte-for-byte incl. start grid (proves `random.ts` bit-identical end-to-end); RANDOM diverges from C as expected but every sampled board is solvable. **The rendering pipeline took three iterations** after this port shipped non-functional (wrongly declared "done" with a "cosmetic/out of scope" deferral the owner had not approved). The full sequence: (a) `5c5eba4` made the midend repaint on every transition + drive the animation/flash timer; (b) `b7dc206` deferred the first animated frame to the timer to remove a frame-0 flicker, and `add-parity-gated-registration` encoded the doctrine; (c) `9823acd` mirrored `midend.c`'s `first_draw` + drawstate-recreation-in-`size()` too literally — fine for upstream's frontend, wrong for ours where `ResizeController` calls `puzzle.size()` on every layout perturbation; (d) `b49bfdb` reshaped that into a side-effect-free `Midend.size` + explicit `EngineCore.canvasCleared()` (called only by the adapter's `resizeDrawing`, the real canvas-clear signal), and moved the background fill from the engine into each game's `!ds.started` branch so the engine emits no pixels of its own; (e) `b1b0dd6` fixed a real state-machine bug — `Midend.timer` accumulated `flashTime` unconditionally, so Flip's `flashTime ? ... : -1` check activated the solve-celebration flash overlay on every animated move (the "wave through every cell" symptom). The fix mirrors `midend.c` lines 1429-1432: reset `flashTime` when the flash either completes or was never armed. **Flip is at owner-confirmed parity as of 2026-05-20.** The lessons spec-enforced: green suite ≠ parity; engine paints no pixels of its own (`fix-flip-canvas-reshape`); manually-maintained per-frame animation state is fragile — but see the entry below: the scene-graph lift that intended to address that fragility was tried and withdrawn, and the doctrine fixes from `fix-flip-canvas-reshape` are what actually carry the weight. Behavioural coverage covers the rendering paths that failed: input-mapping, `executeMove` purity, recording-`GameDrawing` redraw-ops, reshape-with-same-tile, `canvasCleared` invalidation, flash-overlay isolation (438 tests).

- **Scene-graph reconciler experiment** (`scaffold-scene-graph-game-contract` + `add-scene-graph-reconciler`, **withdrawn 2026-05-21**): scaffolded the direction, implemented a declarative `Game.scene` + per-frame reconciler in `src/engine/{scene,reconciler}.ts`, and rewrote Flip on it as the pilot. Owner-acceptance surfaced a visible animation perf regression (the implementer also failed to run the dev server before declaring done — explicit CLAUDE.md rule, the same green-suite-isn't-parity sin `add-parity-gated-registration` was written to prevent). The follow-on conversation widened past the perf bug into "does this pivot belong in the migration window at all?" and concluded no — Flip is too simple to actually pressure the contract; the doctrine fixes from Flip's three-iteration story (engine emits no pixels, side-effect-free `Midend.size`, `canvasCleared` as the only cache-stale signal) cover the cache-fragility class of bugs on their own; cross-game features in the plan (`findMistakes`/`hint`/quick-save) are `Game`-interface hooks + app-shell, not load-bearing on scene-graph. The direction is dropped from the migration plan, not deferred — revisit only if a real game (most plausibly Galaxies' cell↔dot aid, or later overlays) creates concrete cross-game-rendering pressure that's hard to solve per-game. The experimental implementation is preserved at `origin/withdrawn/scene-graph-reconciler`; full rationale at `openspec/postmortems/2026-05-21-scene-graph-withdrawal.md`.

- **Second game port: Galaxies** (`add-galaxies-ts-port`, **at owner-confirmed parity 2026-05-26**): migration-order item 3. `src/games/galaxies/` implements `Game<GalaxiesParams,GalaxiesState,GalaxiesMove,GalaxiesUi,GalaxiesDrawState>` across six files — `index.ts` (Game glue + move logic + types), `state.ts` (typed-array grid + check_complete + DSF-based completion check), `solver.ts` (the four deductive rules + bounded recursion at Unreasonable), `generator.ts` (dot placement + retry-until-target-difficulty loop), `render.ts` (imperative `redraw` with per-tile cache, dot-move animation, win flash), `dsf.ts` (a 56-line idiomatic `Dsf` class — lazy idiomatic leaf port, *local* to galaxies per design D1 until a second consumer appears). All six upstream presets (7×7/10×10/15×15 × Normal/Unreasonable), lenient param decode, drag-to-associate (`RIGHT_BUTTON`/`RIGHT_DRAG`/`RIGHT_RELEASE`), edge-toggle (`LEFT_BUTTON`), keyboard cursor with `UI_UPDATE`, solve, win flash, dot-move animation interpolating along the upstream `movedot_cb` path. `puzzles/galaxies.c` deleted (per-game C deletion); `puzzles/auxiliary/galaxies-trace.c` was used to generate the frozen reference snapshot then removed in the same change. Differential check shape mirrors Flip's: **gated** `galaxies-differential.test.ts` against `__fixtures__/galaxies-c-reference.json` (every C-built board uniquely solvable at exactly the C-recorded difficulty under the TS solver — D7's "tighten the bar, not the comparison") + **advisory** `scripts/diff-galaxies.test.ts` (same assertion, kept per Flip precedent). Test count: ~480.

  **Counts and shape**: ~3000 lines TS (excluding tests) vs ~4500 lines C — *smaller and more readable* (the rare combination where idiomatic-throughout was the right call, not a tradeoff). Wins on three axes: (1) **solver readability** — discriminated `IMPOSSIBLE`/`NOTHING`/`PROGRESS` return codes vs C's magic `-1/0/1`, `solverObviousDot` is ~15 lines of pure logic vs ~23 in C of which ~60% is `solvep(...)` debug-print noise; (2) **move encoding** — C's 140-line `execute_move` with `sscanf` and `goto badmove:` becomes a `GalaxiesMove` discriminated union the type-checker fully covers; (3) **state + GC** — `cloneState` is 13 lines, cannot leak; parallel typed arrays (`flags`/`dotx`/`doty`/`nassoc` in `state.ts`) clone cheaply per-`executeMove`, avoiding both object-per-cell GC pressure and explicit `dup_game`/`free_game`. The 6-file split (vs Flip's 968-line single file) was net positive — Galaxies in one file would have been hostile to navigation.

  **One real bug surfaced on owner-acceptance**: `mkhighlightBackground` in `index.ts` had a near-white epsilon defect (fixed 2026-05-23). That logic is shared puzzle-collection infrastructure (`misc.c` `game_mkhighlight`) and will be re-derived by every white/black-tile game that follows; the natural fix is `src/engine/colour-mkhighlight.ts` — see "Helper extractions queued before next port" below. **Doctrine note 2026-05-23 (owner-explicit)**: the parity gate split into two stages — register the game (task 9.1) as soon as the automated suite is green so the owner can smoke-test the TS path in `npm run dev`; flip `TS_PORTED` + delete `.c` (tasks 9.5/9.6) only on owner-acceptance. The empty-registry fallback covered Galaxies during smoke testing; the same split should be the default for every future port. Memory note: `feedback_parity_gated_no_premature_done.md`.

  **Post-parity cleanup (2026-05-26)**: applied alongside the catalog flip and C deletion. (a) `solver.ts:376-408` lost the ~25-line C explanation of the `iscratch[index-1]` sidecar-slot trick during the port; restored as a TS-flavoured paraphrase so a first-time reader of just the TS can decode why `iscratch[i - 1]` is safe. (b) `render.ts` cache key replaced `BigInt64Array` with `Int32Array` (flags | dots fit in 30 bits; ddx/ddy moved to the cache-miss check via the existing `dx`/`dy` `Int16Array`s) — `BigInt` is hot-path-expensive and idiomatically wrong here; Flip used `Int16Array` for the same role. (c) `index.ts` lost the stale `void RIGHT_DRAG; void LEFT_DRAG; void LEFT_RELEASE;` block (RIGHT_DRAG is actually used; LEFT_DRAG/LEFT_RELEASE and `CORNER_TOLERANCE` were unwired placeholders) — replaced with a single comment naming which buttons Galaxies handles and which it deliberately ignores.

- **Shared-helper extraction** (`extract-shared-helpers`, 2026-05-26): the post-Galaxies prep change. `src/engine/colour-mkhighlight.ts` (epsilon fix included), `pointer.ts` (button constants), `dsf.ts` (`Dsf` promoted from Galaxies). The typed `PointerAction` categoriser shipped here too but found zero adopters across the next two ports and was removed in `refactor-pre-port-tidy`.

- **Third game port: Pegs** (`add-pegs-ts-port`, owner-accepted 2026-05-26): the pattern-validation small game, ported on top of the fresh helpers. `src/games/pegs/index.ts` — three board types (Cross/Octagon/Random with reverse-move generation), drag-to-jump with a blitter-based drag sprite, keyboard cursor with jump-select, per-tile cache, win flash. `SortedMultiset` promoted from Flip-local to `src/engine/sorted-multiset.ts` (Pegs is its second consumer). `puzzles/pegs.c` deleted. - **The colour palette: from 388 literals to twelve colours** (four changes, `audit-game-colour-palette` → `hand-author-dark-palette` → `colour-tokens-per-scheme` → `consolidate-colour-palette`, the last **implemented 2026-08-01, owner acceptance on the appearance pending**). The collection began with a hand-written RGB triple at every site — 388 of them across 56 games in 108 distinct values, already drifted in ways nothing could catch (a render snapshot records whatever the game emits, so a second spelling of an existing colour is invisible to the suite). The first three changes named every colour, authored a dark scheme, and gave each a home *without moving a single value*; the fourth cut the resulting ~190 names down to a designed set.

  **The shape now is three layers.** `src/engine/colours.ts` is **the palette**: twelve names (eight hues, plus grey, brown, black and white), most at three intensities named for their *role* — the base colour, `_WASH` (a fill content is drawn on top of) and `_BOLD` (the emphatic end). It is authored in **OKLCH** with a ~20-line inlined OKLab→sRGB conversion rather than the app's colour library, because the module is reached from the puzzle worker; a third scheme is one more column in its table. `palette.ts` holds the **meanings** (`ERROR`, `HINT_ACTION`, `CURSOR`, `HELD`, `DRAG_ADD`…), every one a *reference* into the palette, so restyling red restyles every meaning built on red — checked **by identity**, since a meaning holding its own value is a colour decision wearing a role's name. `palette-games.ts` (1125 → ~410 lines) keeps only colours defined **relative to a game's own board**, which have no value to author because they are functions, plus exactly one argued absolute exception (Unruly's tile colours are bevel *bases*, where near-black is headroom rather than a shade).

  **The size is not taste, and that is the point.** Flood, Guess and Samegame need ten members a player can tell apart, in every scheme, and nothing else the collection does needs more — so the lightnesses are the *output* of a search maximising the worst pairwise OKLCH distance in every set at once, and `colours.test.ts` re-measures all of them against what upstream's hand-written sets actually scored: ten (flood/guess) 0.134 → **0.159** light / **0.143** dark (was 0.070); samegame 0.127 → 0.159; mines' six counts 0.142 → 0.159; signpost's eight fills 0.071 → 0.087; map's four 0.077 → 0.115. The dark column is why authoring was necessary at all: **mutual distinguishability is a relation between members**, so no rule applied to one colour — including adapting it to a scheme — can establish or preserve it.

  **Four things measurement decided that judgement would not have.** (a) *Brown is not a hue* — at the wash and bold steps it and orange are 0.01 apart, because brown **is** dark low-chroma orange; it stays its own name only because it must not invert (orange's bold step goes light in dark mode) and Flood says it to the player. (b) *An intensity may not be named for its appearance* — a wash is light under a light scheme and **dark** under a dark one, so `_PALE` would be false in one of them, which the truthful-name rule forbids for anything a player can see. (c) *Mines forced the third intensity* — 1-blue against 4-navy and 3-red against 5-maroon must read as **digits**, and a wash is a fill. (d) *`HINT_EVIDENCE` changed hue rather than becoming a third blue* — seven games paint evidence and target at once and the two were eight hundredths of a lightness apart; the distinction survives a hue change and did not survive a shade change.

  **Crossing's OKLCH-matched dimension pair moved into the palette** and immediately justified the move: blue's and orange's wash *and* bold steps are now tied in lightness and chroma, and the first cut tied only the wash pair — caught by Crossing's own equal-strength test. A game cannot be trusted to maintain a constraint that is really the palette's.

  **What only owner acceptance caught, and the shape of it.** Three defects survived a green suite, and all three are the same mistake: *a search maximises what it is given and buys it with anything not bounded*. Dark `YELLOW` was pushed to lightness 0.95 at half its available chroma — the lightest entry in the palette, a **cream** — because that is where the ten-set's worst pair was largest; capping it at 0.86 costs the set 0.158 → 0.143, and that number is the honest one, because the 0.158 *was* the defect. Four dark washes sat below the lightness a game draws its own cells at, so Crossing's across/down highlight came out darker than the squares it highlighted and read as a hole in the board — the wash rule ("dark enough for light text") was a bound in one direction only. And fixing yellow exposed a third: with its base near the top of its gamut, the search inverted yellow's **bold** step to sit *below* the base, which is not a weaker bold but the wash wearing its name. All three are now assertions in `colours.test.ts` rather than comments. Generalises past colour: **an optimised artefact needs its bounds asserted, because the objective will never complain about what it is trading away.**

- **The engine's test *feedback*, measured properly — and the metric it was scoped around was an artefact** (`strengthen-engine-test-feedback`, 2026-08-02). `audit-test-suite-strength` ended with a **"killed by its own test file"** column and this change was proposed to move it, opening on *"the two extremes, `grid.ts` and `latin.ts`, first."* Checking the instrument before trusting it — the audit's own most-repeated lesson, and by now this repository's standing rule — showed the column measures something else entirely.

  **Stryker bails the test run on the first failure**, so `killedBy` names *the first covering test to fail*, not the tests capable of catching the defect: all 1,437 killed mutants in that report have exactly **one** entry. Vitest orders files roughly alphabetically, so `grid.ts` scored 1/40 because `grid-aperiodic-differential.test.ts`, `grid-desc.test.ts` and `grid-incentre.test.ts` all sort ahead of `grid.test.ts`. Deleting the `case "cairo":` arm and running `grid.test.ts` **alone** fails nine tests in 1.5 s. **The correction reverses the ranking**: `grid.ts` catches **6 of 6** and needed nothing, while the genuinely worst module was `midend.ts`, which the artefact had rated a comfortable mid-table 39%.

  **`npm run probe` is what replaced it** — `scripts/feedback-probe{,-cases}.mjs`, 72 hand-chosen real defects, each applied to the source with **only the module's own tests** run against it, which is the property the `repo-layout` requirement actually states. Four things it does deliberately: it **aborts on a missing or non-unique anchor** (it fired on its very first invocation, and each such case would otherwise be a clean `SURVIVED` measuring nothing); it **derives "own tests" mechanically** as every engine test file importing the module, because naming one file is the audit's §5a unit mistake in the mirror direction (eight files drive a `Midend`); it **excludes differentials even when engine-local**, so a module cannot score full marks on assertions it does not make; and it carries **`equivalent: true` cases with their argument**, excluded from the rate rather than chased — flagging one that later starts being *caught*, since that means the argument expired.

  **Result: 43/69 → 70/70, for +49 tests and +4.9 s of gate CPU (+2.9%, wall clock unchanged).** `latin.ts` 33% → 100% (854 lines and eleven consuming games behind four end-to-end tests; each deduction now has a direct test in its own vocabulary, plus `matching` against a brute-force maximum). `midend.ts` 41% → 100%, and its gap was **mostly sentences a player reads**: `loadGame` has four distinct refusals and only the puzzle-id one was covered, and "This game does not support solving / hints" is a path where returning `undefined` means *done*. `wires.ts`' `growSpanningTree` — the solved grid every Net board is scrambled from — had **no local test at all**.

  **`dsf.ts` is the one to reread**, because it is what "well covered but silent" looks like from the inside: its tests *do* assert `size()` and *do* cross-check 200 random merges against a brute-force reference, but every hand-written merge joins **equal-sized** classes, so the `classSize[ra] > classSize[rb]` branch is never taken, and the property check compares class *membership* rather than roots. Both halves of union-by-size were unasserted — on a rule whose own doc comment records that upstream branches on the canonical root's **identity**.

  **Two survivors were argued equivalent rather than killed**, and working out *why* on the second corrected a comment in `border-grid.ts` that the module's own test already contradicted. **The timeout question was answered from the existing report at zero cost**: the two modules with no loop at all had **zero** timeouts across 125 mutants, and the rate runs *inversely* to covering-set size — the opposite of what contention predicts. Genuine non-termination; budget a re-run at the same ~400 minutes.

  **Extended by blast radius, not by where the audit looked** (`extend-feedback-probe-corpus`, same day): four more modules picked by importer count — `params.ts` (**90 importers**), `colour-mkhighlight.ts` (37), `findloop.ts`, `grid-core.ts` — took the corpus to **93 cases across 14 modules, all at 100%**. `params.ts` had **no test at all** for `atof` and `formatG`, the two functions whose doc comments spell out a silent-failure mode: `atof` returns 0 rather than `NaN` because `NaN < min` *and* `NaN > max` are both false, so a typo in a custom-params box would slip past every bound check; `formatG` is C's `%g` rather than `String(x)` because a float param at full double precision reads back as a *different* number and the game ID stops naming its board.

  **And `grid.test.ts` held a vacuous assertion** — the most reusable finding of the two changes. `expect(d.edges.length).toBe(d.order)` ran across all eighteen tilings and **cannot fail**, because `d.edges` is allocated `new Array(d.order)`; halving every dot's degree in the grid builder passed all 151 tests in the file. **Grep for the shape: `x.length` against the thing that sized `x`, a getter against its own field, a total against the sum it came from.** The replacement counts the degree independently, and bounds the real exception rather than dropping it ("at most one null face, and only where the infinite exterior breaks the ring" — the first attempt forbade nulls outright and failed 28 tilings). Both are now `repo-layout` scenarios. `mkhighlight`'s saturate-to-white arm went the other way: **unreachable, settled by sweeping 9,261 backgrounds** over the RGB cube rather than by argument, so it is recorded equivalent and the code kept.

  **And one defect the entire gate was blind to.** Writing a "feed it garbage" test put a literal **NUL byte** into `save.test.ts`. tsc compiled it, biome formatted it, the test went green, `vite build` built — and the only signal was `git diff --stat` printing `Bin 6264 -> 9595 bytes`, because git treats a file containing NUL as binary and **stops diffing it**. A file whose changes cannot be reviewed is far worse than the byte that caused it. `src/asset-integrity.test.ts` now forbids raw C0 controls in any `.ts` file (the regex had to be written with escapes or it would flag its own file). The transferable half: **"the test passed" is not evidence the test file is well-formed** — the assertion and the committed artefact are different things.

- **`src/native/` retired; the engine now owns its own vocabulary** (`retire-native-directory`, 2026-08-02, **owner acceptance pending**).   **Two guards were found measuring the wrong thing, both while resolving test-only reaches.** `touch-input.test.ts` asserted `puzzleIds.length > 25` — the *catalog's* length — while every iteration of its sweep did `if (!game) continue`, so an empty **registry** would have skipped all 57 games and still passed; `custom-params.test.ts` had no guard at all. Same family as `grid.test.ts`'s `d.edges.length === d.order`: **a guard measuring a neighbour of the thing it claims to guard.** Both now read `registeredGameIds()` once at collection time and assert that count. It recorded the subsets of a set — what the definition requires, not an upstream quirk — while the file already asserted `C(n, r)`, strict lex order and distinctness exhaustively over `n ≤ 8`. Deliberately **not** a precedent for the 48 per-game differentials or `random`'s corpus, which record facts that cannot be derived. The reusable part is the scoping question: **not "is this fixture's subject derivable?" but "is *every* fact this fixture asserted derivable?"** — the corpus block was also the only place `reset()` was ever driven, a scenario the spec requires.

  **And the method finding, which generalises past this change.** A bulk import-rewriter must match specifiers in import *position*. Matching "any quoted string starting with a dot" hit prose in doc comments (`'1'..'9'`, `"no-track"` — it swallowed the real import line below and silently *skipped* the file) and ordinary code literals, where `"."` → `"./"` rewrote `formatAsText` output in a dozen games and `params.ts`'s `formatG`. Nothing failed. What caught it was **verify-by-shape**: assert every changed line in the whole diff is an import line, then read the exceptions. The same method proved the spec sweep — all 71 changed lines are exactly the prefix substitution — and the design's own prescribed check was too weak for that job, since `grep -v 'src/native/…'` only inspects the `-` side. The one thing no string sweep can see is **path arithmetic keyed to depth**: `scripts/metrics-summary.mjs` derived a game id as `p.split("/")[3]` and would have gone on returning a *filename*.

- **Two crowded directories split, and the instrument taught to follow** (`group-crowded-source-directories`, 2026-08-02, **owner acceptance pending**). The second post-C source-tree change, and a readability one — proposed on the standing "noticeably cleaner is sufficient" directive, not on a defect history. `src/engine/` gained exactly two subdirectories, `grid/` (fifteen modules, their fixtures and the aperiodic `tilings/`; `grid.ts` → `grid/index.ts`, the barrel its own doc comment already told callers to import from) and `colour/` (the three layers `consolidate-colour-palette` designed). Nesting `grid/` under it would not have errored — the derivation would simply have shrunk, so more cases report `SURVIVED` and **the rate drops**, which reads as *"the tests got worse"* rather than *"the instrument stopped looking"*. The anchor check cannot cover it: anchors quote source **lines**, and a pure move leaves every one valid. The walk is recursive now, with a **committed floor on the number of test files found**, placed inside `--verify` so it rides in the commit gate — and *proved to fire* before being trusted (forcing it flat gives `discovered only 46 … floor is 50`, exit 1). Recursion also made the derivation more *correct*, not merely move-proof: `tilings/spectre.test.ts` is now a local test of `grid`, and `testing/render-scenario.test.ts` one of `border-grid`. Baseline and post-move probe both **90/90, 3 equivalent, all fourteen modules at 100%**.

  **Three constructs a bulk import-rewriter is structurally blind to, all found in moved files.** `retire-native-directory` recorded that a rewriter must match specifiers in import *position*; this change found that matching import position is **not sufficient**, because a file names its siblings in three other ways. `import.meta.glob("../games/**/*.ts")` — **silent**, since an unmatched glob yields `{}` and `palette-source.test.ts` would have reported "no game contains a colour value" across three passing assertions. `new URL("../assets/icons/…", import.meta.url)` — loud, `asset-integrity.test.ts` asserts every one resolves. And underneath the glob, the same **depth-keyed path arithmetic** the previous change flagged: `path.replace("../games/", "")` left `../abcd/render.ts`, turning the game id into `".."`. What caught the silent one was the file's own `expect(sources.length).toBeGreaterThan(100)` — the *"how many things did I look at?"* guard, now on its fourth appearance here. The derivation was rewritten to cut at `/games/` and **throw** when the match fails, which is correct at any depth.

  **And the "resolve-and-re-derive" rewriter needs a guard the prefix version does not.** Mapping each specifier to a repo path, through the move table, and back to a relative path is exact where prefix arithmetic is guesswork — it expresses `grid.ts` → `grid/index.ts`, and correctly leaves `tilings/`'s `"../grid-core.ts"` alone because importer and target moved together. But it also *normalises* specifiers nothing invalidated: it rewrote `import "../test-setup/icons.ts";` inside that file's own doc comment, where the line is written from a **consumer's** perspective. The fix is one line — touch a specifier only when the target moved or the importer did — and verify-by-shape caught it, again.

  **Two defects found by taking a baseline rather than by the move.** `npm run diff` — the check `design.md` D5 nominates as most likely to notice a lost colour module — had been failing `ENOENT` **since 2026-08-01**, because `colour-inventory.test.ts` wrote into `openspec/changes/consolidate-colour-palette/`, and `openspec archive` renames that directory. Nothing said so, because an advisory run reports rather than gates. Output now lands in `metrics/colour-inventory.md`, and the regenerated file is **byte-identical** to the archived copy — which is simultaneously the pre-move baseline and proof the colour tree had not drifted. The rule, now in the spec: **a tool must not write into a change directory; the path has an expiry date built into the workflow.** (The second: `README.md`'s `[LICENSE](./LICENSE)` pointed at a file that is `LICENSE.md`.)

The suite is 252 files / 6622 passed / 6 skipped **both sides**: a comment edit that swallowed a `describe` leaves a green suite with fewer tests in it, the same silent-shrink shape the probe's test-file floor guards. Method note: the sweep's regex matched the verb "regenerate" and so missed five files that say "Fixture recorded by", "can no longer be regenerat**ed** … then:", or carry the recipe as an inline parenthetical. - **The workflow tool was nine months stale, and a whole change had been spent routing around its fixed bug** (`retire-modified-spec-deltas` implemented then **withdrawn**; `upgrade-openspec-tooling`, 2026-08-24, **owner acceptance pending**). Archiving `disambiguate-hint-deixis` (2026-08-15) silently deleted **134 lines** of the `ts-engine` hint requirement, because `openspec archive` replaces a live requirement with a `MODIFIED` delta's stale copy. The owner's question is what surfaced it: *"if we need to fight against the openspec tool, maybe we need to change the tool."*

  **`feedback_check_the_instrument` applies to dependencies.** Checking what the *installed* tool does and generalising it to what "the tool" does is the same error aimed at a package — and the proposal had even stated its own goal as *"guidance is what you write when the tool cannot be trusted; the goal here is a tool that can"*, then failed to notice the way to get one was a version bump. The hand-written check was also **weaker** than what it replaced, lacking four releases of upstream hardening (a requirement keeping one of two same-named scenarios, `#### Scenario:` inside fenced code blocks, level-4 children that are scenarios without the label). **The trigger to watch for is the *feeling* of fighting a tool** — a workaround layer, an override of generated content, a guard that a guard survived. Three commands and two minutes answer it.

The migration was then **rehearsed on a throwaway worktree** before being run, which is what surfaced the symlink question early (`update` names both `CLAUDE.md` and `AGENTS.md`; here one is a symlink to the other — it resolved correctly and edited the target once). Result: 19 deletions from `AGENTS.md`, all managed block; `openspec/specs/` and all **914** archive files byte-identical per git; validate 80 passed either side.

All four delta verbs are available again.

  **Three findings outlived the withdrawal.** (a) **A delta can be faithful to the wrong original** — `add-slide-keyboard-control` modified "Slide input, movement and completion" while its prose announced removing a sentence that lives in "Slide game implements the Game interface"; archiving would have published a spec declaring a keyboard player's exclusion removed while leaving it in force. Both requirements were scenario-complete, so no check on either side could see it. (b) **A scenario name is the requirement's identity**, learned by being caught: this change's own spec edit was written as `MODIFIED` renaming a scenario whose name had become false, and validate refused it, because a renamed scenario reads as a dropped one — a name that contradicts its body cannot be edited into truth, only retired and replaced. (c) The "configurable instruction filename" open question is **closed by removal**: 1.x generates no instruction file, so `openspec/OPENSPEC_AGENTS.md` and the rename dance are gone. The question had assumed its answer must be a setting. Postmortem: `openspec/postmortems/2026-08-24-retire-modified-spec-deltas-withdrawal.md`.

Every white/black-tile game imports this; no game re-derives palette math.
2. **`src/engine/pointer.ts`** — button code constants; all four ported games import them. The typed `PointerAction`/`parsePointerAction` categoriser shipped alongside, but two drag games (Galaxies, Sixteen) then shipped without adopting it, so it was removed as phantom API in `refactor-pre-port-tidy` (2026-06-10). Recover from git history if a future port genuinely wants that shape.
3. **`src/engine/dsf.ts`** — `Dsf` promoted; `sorted-multiset.ts` (`SortedMultiset`) followed when Pegs became its second consumer. `parseLeadingInt` lives in `src/engine/params.ts` since `refactor-pre-port-tidy`.

Still queued, not blocking:
